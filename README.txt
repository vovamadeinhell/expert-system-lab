# Лабораторная работа №1

Экспертная система для диагностики неисправностей компьютера с прямой цепочкой рассуждений.

## Запуск

Требуется Python 3.10 или новее.

```bash
python main.py
```

Правила хранятся отдельно от программы в `rules.txt`. В начальной базе 20 правил для нескольких диагностических ветвей.

## Как строится вывод

При совпадении условий правило добавляет заключение в рабочую память. Полученный факт может стать условием следующего правила. Например, ветвь отсутствия изображения проходит через правила 1, 5 и 8:

1. Правило 1 по ответам о включении компьютера и чёрном экране добавляет факт `Симптом=изображение_не_появляется`.
2. Правило 5 использует этот факт вместе со звуком загрузки и добавляет предполагаемую причину.
3. Правило 8 использует предполагаемую причину и ответ о наличии изображения на мониторе, после чего формирует диагноз.

Есть и другие цепочки: для проблем с питанием, сбоя загрузки, кнопки включения, нормальной загрузки и мерцания экрана. Ход работы показывает каждый сработавший номер правила и добавленный промежуточный факт или диагноз.

## Проверка цепочки 1 → 5 → 8

Запустите консультацию и последовательно введите:

- `Компьютер_включается`: `да`
- `Экран_черный`: `да`
- `Звук_загрузки`: `да`
- `Изображение_на_мониторе`: `нет`

В трассировке появятся срабатывания правил 1, 5 и 8, а диагноз будет `проверить_видеокарту_кабель_и_монитор`. Полный пример диалога находится в `sample_run.txt`.

## Изменение базы знаний

Через меню можно просматривать, добавлять, менять и удалять правила. Новые условия не требуется прописывать в коде. Например, добавьте правило:

`ЕСЛИ Компьютер_включается=да И Корпус_перегревается=да ТО Диагноз=вероятный_перегрев_компьютера`

В следующей консультации объект `Корпус_перегревается` станет вопросом. При ответах `да` и `да` система сформирует новый диагноз. Новая короткая цепочка может изменить как вопросы, так и результат.
